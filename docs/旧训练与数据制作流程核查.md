旧实验文件位于 `/home/tacmon/workspace/ex_SSD/gc_ope`；新代码位于同级 `gc_ope_refactor`。本次没有改写旧实验数据，也没有运行全量训练或全量后评估。

## 1. 实际文件流

```text
scripts/train_policy/shells/my_push/curriculum/sac_omega.sh
  └─ scripts/train_policy/train.py + Hydra 配置
       ├─ checkpoints/my_push/sac/<设置>_seed_N/*.zip、*.pkl
       ├─ logs/my_push/sac/<设置>_seed_N/progress.csv、evaluations.npz、log.txt
       └─ 训练 stdout/stderr → logs_in_process/my_push/sac/my_push_sac_<设置>_seed_N.txt

*.zip → scripts/evaluate_ckpt/evaluate_my_push_slide.py
       ├─ *_eval_res_on_random.csv
       └─ *_eval_res_on_fixed.csv

progress.csv → 训练成功率、回报、KL、alpha 曲线
课程文本日志 → train_log_process.py → 实际选择的 behavioral goals
random CSV 的成功目标 + behavioral goals → 能力密度与课程散点图
fixed CSV + replay buffer → 旧离线估计/KL 中间 CSV → 对应 notebook 曲线
```

## 2. 训练怎样启动、怎样命名

`scripts/train_policy/shells/my_push/curriculum/sac_omega.sh` 的前五条命令是默认正式设置，后面才是 κ、b、候选数、评估预算等消融。入口由 Hydra 组合：

- `algo=sac_for_my_push`：SAC 算法参数。
- `env=my_push_omega`：仅训练环境使用 OMEGA/MEGA 课程。
- `callback=sac_omega`：从周期 policy evaluation 获取能力估计数据，即 PE 路线；`sac_omega_replay_buffer` 是另一条 RB 路线。
- `evaluate=my_push`：训练结束后的总体评估。
- `experiment_name=sac/omega_dscnt_0_9_b_0_n_100_eval_96_seed_N`：同时决定 checkpoint 与普通日志的目录。

正式脚本覆盖为 `kappa=0.9,b=0,sample_n=100`；不能直接把环境 YAML 中未覆盖的 `b=-3,sample_n=10` 当成正式实验参数。五组种子及 GMM 对齐情况见 [GMM 接入说明](GMM课程训练接入与审阅说明.md)。旧脚本使用 `uv run --offline`，本机按用户指定改用已有 Conda `gc_ope`，保留 Hydra 参数。

## 3. 三类训练产物分别保存什么

### 3.1 checkpoint 与 replay buffer

`configs/train/callback/sac_omega.yaml` 经 `get_callbacks.py` 构造原 SB3 CheckpointCallback，每 10000 步保存：

- `rl_model_<步数>_steps.zip`：策略模型，可独立加载做后评估。
- `rl_model_replay_buffer_<步数>_steps.pkl`：经验回放，供旧 RB 分析使用。
- `best_model.zip`：评估回调选择的最佳模型。

用户指定的旧 κ=0.8、seed=1 目录，实际有 100 个周期模型加 `best_model`，对应 random/fixed CSV 各 101 份。回放缓冲区、模型和课程日志用途不同；不要用回放中的 achieved goals 冒充课程实际选中的 desired goals。

### 3.2 普通训练指标

`train.py` 的 SB3 logger 启用 stdout、log、csv、tensorboard，保存在 `logs/<env>/<experiment_name>/`：

| 文件 | 内容与后续用途 |
| --- | --- |
| `progress.csv` | `time/total_timesteps`、`eval/success_rate`、`eval/mean_reward`、`env/KL[p_dg\|p_ag]`、`env/alpha` 等；不同记录行可能有空值，旧 notebook 先过滤非空行 |
| `log.txt` | SB3 指标表格及 logger.info 消息；不包含环境子进程中普通 print 的课程选点 |
| `evaluations.npz` | `timesteps/results/ep_lengths/successes`；每轮 96 条 episode 的回报、长度、成功标记，没有完整 desired-goal 列 |
| `events.out.tfevents.*` | TensorBoard 指标 |

实际读取旧 κ=0.8、seed=1 的 `evaluations.npz`：timesteps 为 10000～1000000，共 100 轮；results、ep_lengths、successes 的形状均为 `(100,96)`。这不能替代 random/fixed 的逐目标 CSV。

### 3.3 课程原始文本日志

旧 `MEGAWrapper` 和 `OMEGAWrapper` 已在每次选择目标时打印：

| 关键词 | 含义 |
| --- | --- |
| `sample from random:` | 没有成功评估数据，原环境随机目标 |
| `sample from omega random:` | OMEGA 的 alpha 随机探索分支，含目标、KL 和 alpha |
| `find min: point ... with score ...` | MEGA 选取阈值以上密度最低的候选 |
| `find max: point ... with score ...` | 全部候选都低于阈值时，选取密度最高候选 |

实际旧文件为：

```text
logs_in_process/my_push/sac/my_push_sac_omega_dscnt_0_9_b_0_n_100_eval_96_seed_1.txt
```

该文件约 27.6 MB，本次逐行统计到 205 条初始随机、36009 条 OMEGA 随机、9231 条 find min 和 2084 条 find max。与之对应的普通 `logs/.../log.txt` 中，这四类记录均不存在。因此，“SB3 已启用 log 格式”不等于“课程选点已经保存”。

旧脚本未写出将 stdout 保存到上述文件的终端重定向命令。现存完整日志和 notebook 引用证明了输出目录、命名与格式；不能据此声称已经找到师兄当时具体使用的 `tee`/重定向命令。本次启动脚本显式使用 tee 完成相同的落盘，并设置 `PYTHONUNBUFFERED=1`，保证子进程 print 不滞留在缓冲区。

## 4. 后评估必须用 evaluate_ckpt

旧入口是 `scripts/evaluate_ckpt/evaluate_my_push_slide.py`，对应十条命令在 `scripts/evaluate_ckpt/shells/my_push/sac_omega.sh`。本次核对该脚本、评估实现、日志解析器与 `dev` 均无差异。

- random：`eval_cfg.dg_gen_method=random`，`eval_dg_num=1000`，在目标空间随机生成 1000 个测试目标。
- fixed：`eval_cfg.dg_gen_method=fixed`，XYZ interval 均为 0.02。Push 的 z 固定为 0.02，XY 各 26 个值，共 676 个目标。
- 目标集合在遍历 checkpoint 前生成，同一次调用中的所有模型使用这一集合。评估脚本遍历目录中所有 `*.zip`，也包括 `best_model.zip`。
- CSV 写在模型旁边，后缀为 `eval_res_on_random` 或 `eval_res_on_fixed`。
- 旧字段为 `x,y,z,length,termination,achieved x,achieved y,achieved z,cumulative_rewards,discounted_cumulative_rewards`；成功使用 `termination == "reach target"` 判断。
- 旧五 seed random 命令的 seed 是 `[12,25,39,47,51]`，fixed 是 `[15,28,33,41,56]`。这些是旧命令参数，不据此额外保证旧 random 目标生成具备完整的随机数复现性。

**`scripts/evaluate_new/evaluate_my_push_slide.py` 是 replay-buffer 目标评估。** 它加载每个 checkpoint 对应的 `.pkl`，从 achieved goals 取评估目标。这和 random/fixed 是不同数据源，不能因名字带 new 就拿来替代旧入口。之前 AGENTS.md 中指向 evaluate_new 的笼统描述已修正。

例如，GMM seed 1 训练完成后，可直接复用旧评估器，唯一更换 checkpoint 路径：

```bash
conda run -n gc_ope env PYTHONPATH=src python scripts/evaluate_ckpt/evaluate_my_push_slide.py \
  algo_type=sac ckpt_dir=checkpoints/my_push/sac/omega_gmm_dscnt_0_9_b_0_n_100_eval_96_seed_1 \
  env=my_push process_num=32 eval_cfg=my_push_random_dg_set \
  eval_cfg.dg_gen_method=random eval_cfg.eval_dg_num=1000 gamma=0.95 \
  eval_res_csv_file_suffix=eval_res_on_random seed=12

conda run -n gc_ope env PYTHONPATH=src python scripts/evaluate_ckpt/evaluate_my_push_slide.py \
  algo_type=sac ckpt_dir=checkpoints/my_push/sac/omega_gmm_dscnt_0_9_b_0_n_100_eval_96_seed_1 \
  env=my_push process_num=32 eval_cfg=my_push_random_dg_set \
  eval_cfg.dg_gen_method=fixed eval_cfg.x_interval=0.02 eval_cfg.y_interval=0.02 \
  eval_cfg.z_interval=0.02 gamma=0.95 eval_res_csv_file_suffix=eval_res_on_fixed seed=15
```

上述是旧 32 进程设置的等价入口示例，本次没有执行。旧评估器会重写同名 CSV，没有自动续跑检查，不能把它描述成已有防覆盖功能。

## 6. 旧流程的实际边界，不自行改写

- **完整原始日志与旧图选点不是同一个范围。** 随机分支打印在原始日志中；旧 notebook 明确只取 find min/find max。旧解析器要求 `with score`，因此即便传入 omega-random 关键词，其无 score 的行也不会成功进入结果。不能说旧课程图包含所有选择。
- **旧 timestamp 是日志表格中的最近一次 total_timesteps。** 解析器顺序读文本，遇到该字段更新当前时间，再分配给后续选点。它不是精确逐 episode 时间；子进程 stdout 顺序也可能影响邻近时间的归属。此次保留该流程，不改时间定义。
- **模型 checkpoint 不能重建当时所有实际随机选择。** 后评估能重建能力测量，课程选择仍需训练时的过程日志。
- **96 条在线评估与 100 条离线模拟抽样不同。** npz 保存在线评估结果；旧离线 notebook 从 fixed CSV 有放回抽 100 条，不能把该模拟结果称作训练实际使用过的同一批目标。
- **旧分析代码也可能有命名错误。** `my_push/plot_omega.ipynb` 中 `sac_omega`/`sac_omega_rb` 分支的显示标签疑似互换；本次只记录，未改图或协议。PE/RB 仍应以 callback 配置和真实数据源为准。
