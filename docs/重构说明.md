## 实验定义

对当前 checkpoint `t`，从每份 `s <= t` 的 fixed-eval **全部记录**中有放回
抽取 100 条，包含当前 checkpoint。每份文件的抽样由
`SeedSequence([sampling_seed, 1, training_seed, source_checkpoint])` 决定，
不依赖方法、待估计 checkpoint 或并行顺序。成功和失败标签一起保留。
样本权重为 `0.9 ** ((t-s)/10000)`。抽样索引与保存版本的 history100 协议一致。

每种方法创建两个全新实例，超参数相同：

| 一侧 | 输入 | 拟合方式 |
| --- | --- | --- |
| 历史估计 q | 每份文件的 100 条记录，累计至当前 | 带时间权重 |
| 当前参考 p | 当前 fixed CSV 全量记录（实测 676 条） | 权重全部为 1 |

GMM、NF、FM（及可选 KDE）只拟合成功目标。NN 两侧都用成功/失败标签训练
MLPClassifier，然后在相同几何支持网格上预测成功率，以归一化预测概率作为
高斯核权重。网格仅提供坐标，历史分类器不会读取未抽中的当前真实标签。
NN 密度是连续且积分为 1 的核混合，具有明确的采样方法。

`KL(p || q) ≈ mean(log p(X) - log q(X))`，其中 `X ~ p`。
每次采样 10000 个，按上一轮配置保留 5 次独立重复，保存均值、重复间标准差
及每次原始数值。标准差不是均值的标准误。使用自然对数，单位为 nat。
有限 MC 可能得到小负值，保留原值。

所有默认 KL 在原始 XY 坐标中计算；各模型内部可以独立标准化，但评估密度时
正确换算 Jacobian。高斯/流模型定义在整个平面，采样不截断到目标矩形，
因为截断会改变分布和归一化常数。

Push 的 z 固定。旧 `env/utils/my_push/desired_goal_utils.py` 也只枚举 XY，
使用二维面积；新模型沿用这个几何定义。旧 KDE 默认三维接口没有改变。

## 保留什么，改变什么

| 类别 | 内容 | 验证方式 |
| --- | --- | --- |
| 结构迁移 | 估计器继续使用旧容器、fit/evaluate 四元组；数据、KL、调度分开 | 单文件测试与真实环境检查 |
| 保持行为 | GMM 加权重采样、NN 分类器、NF 加权 NLL、FM 加权目标抽样 | 与 a053348 四方法数值对照 |
| 接口修正 | NF 的 `scale=False` 表示已标准化输入；NF 初始化不污染全局随机流 | 密度契约及 NumPy/Torch 状态检查 |
| 新协议 | 参考侧改用同方法独立拟合；NN 加高斯核平滑 | 双模型身份、数据条数、积分和采样检验 |
| 新能力 | GMM/NN/NF/FM 可从模型采样，接入课程 wrapper | 解析高斯/线性流检查、Push/SAC 短训练 |
| 调度入口 | 通用入口使用单池；专用全量入口按 NN→FM→NF→GMM，每方法五 seed 各四 worker | CLI 续跑、锁与中断清理检查 |

通用入口默认共 4 个 CPU worker；按用户后续指定，专用全量入口使用五 seed
各四 worker，共最多 20 个计算进程。两者均为 CPU、BLAS 单线程，复用同一
实验逻辑。调度不改变抽样和拟合输入，每个任务保留独立日志和诊断 JSON。

旧 `utils/kde_dist.py` 的独立标准化/低密度过滤代码完整保留。新 MC 工具也
保留 `legacy` 对照模式，但不能把该模式叫作原始目标空间 KL，也不能将它
与默认模式混合续跑。用户无需选择这个术语，正式入口默认按上述分布定义执行。

两侧改用同方法后，不同方法的参考分布也不同。因此这衡量的是“同种估计器用
少量历史数据，相对于本方法全量拟合的差异”，不能仅凭 KL 大小断言哪一种方法
更接近共同的真实能力分布。尤其 NN 若两侧都预测得接近均匀，KL 可以很小。

旧 KDE 投稿结果继续只作为 **legacy 对照**，来源是原目录
`plots/p_ag_dist_between_truth_and_estimated_in_training/my_push/sac/eval_data/`
中五个 seed CSV 的 `$D_{KL}$ [his]`。旧抽样索引未知，标准化、过滤、带宽和 MC
重复次数仍有差异，不能宣称已完全同口径。这里没有重算或改写这些 CSV。

## 代码阅读顺序

1. `src/gc_ope/evaluate/offline_data.py`：fixed 文件、100 条共享抽样、时间边界与权重。
2. `offline_experiment.py`：一条实验从读取到两侧拟合，再到 KL 的完整流程。
3. `evaluator_factory.py`：共用构造入口与默认参数。
4. `evaluator_gmm/nn/nf/fm.py`：各自的拟合、密度查询和采样算法。
5. `utils/distribution_kl.py`：连续 KL，旧工具仍单独保留。
6. `offline_results.py`、`scripts/evaluate_push_estimators.py`：清单、日志、续跑与调度。
7. `evaluator_planar.py`、原 `mega_wrapper.py` / `omega_wrapper.py`：训练接入。

没有引入新的训练框架。已有 `scripts/train_policy/train.py` 和 Hydra 配置继续使用。
不传 `estimator_config` 时，课程学习仍走旧 KDE 路径。
NN 单类、NF/FM 成功样本不足等情况，离线明确跳过，在线退回环境目标采样；
真正的数值或实现错误会报错，不会伪装成数据不足。

课程学习中的 `KL(均匀目标分布 || 能力分布)` 继续使用旧 OMEGA 网格积分，
这里的比较对象与离线两模型 KL 不同，不改成两模型 MC。在线回调每轮仍是旧配置
`6 × 16 = 96` 条评估，离线每 checkpoint 抽 100 条不等于要求修改在线回调预算。

## 后续运行命令（尚未启动全量）

以下命令都在 `gc_ope_refactor` 中执行，输入根目录显式指向原数据。
离线脚本固定从自身 worktree 导入；训练和测试显式设置 `PYTHONPATH`。

```bash
# 正式全量：四方法串行、五 seed 并行、每 seed 四 worker。
# 脚本内部自动进入 gc_ope Conda 环境；中断后原命令续跑。
bash scripts/run_push_all100.sh
```

专用入口完整参数与日志说明见 `scripts/README_push_all100.md`，默认输出为
`logs/push_same_family_all100_5x4/`。下面的单方法参数说明对应保留的通用入口
`scripts/evaluate_push_estimators.py`。

省略 `--checkpoints` 时，入口要求每个 seed 存在从 10000 到 1000000 的 100 份
fixed CSV。不会因为文件缺失便悄悄缩小覆盖率。某个配置想逐方法补完时，应从
开始就使用独立输出目录，例如 `--methods gmm --output logs/push_same_family_gmm`；
已有运行保持原始 methods/seeds/checkpoints 参数，入口会自动只补缺失和错误行。

完整展开的协议配置、输入与代码 SHA256、库版本写入 `config.json`；数据、代码、
参数变化时拒绝续跑。CSV 每 checkpoint 一行，重试原子替换；完成后生成
`audit.json`，同时检查覆盖率、额外行和非有限值，不只看进程退出码。
早期样本不足的跳过也占一个 checkpoint，不能称为有效 KL。
新 CSV 不包含 `fixed_grid_kl`，方法标识为 `nn/fm/nf/gmm`；旧绘图脚本留在
原目录，不自动把不同协议的结果拼成旧图。画新图时应读取新 CSV 的 `kl`。

```bash
# 未来正式 Push/SAC + OMEGA 训练入口示例；本次没有运行这个长训练。
# 将 method=gmm 换成 nn、nf 或 fm 即可；更换方法也请更换 experiment_name。
conda run --no-capture-output -n gc_ope env \
  PYTHONPATH=/home/tacmon/workspace/ex_SSD/gc_ope_refactor/src \
  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python scripts/train_policy/train.py \
  env=my_push_omega_estimator algo=sac_for_my_push callback=sac_omega evaluate=my_push \
  env.curriculum_kwargs.estimator_config.method=gmm \
  algo.device=cpu algo.seed=1 env.train_env.seed=1 \
  experiment_name=sac/omega_gmm_seed_1
```

正式在线实验的预算、seed 组合和训练耗时还需要单独验收。FM 在每次新评估数据
到来后重新拟合 500 次更新，在线开销可能显著；本次不以短训练推断百万步成本。
